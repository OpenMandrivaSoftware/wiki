# Ciclo de vida de uma versão de software

Da [Wikipédia, a enciclopédia livre](https://en.wikipedia.org/wiki/Software_release_life_cycle)
*Extraído e adaptado livremente.*


## Etapas de desenvolvimento e lançamento final

### Prévia e Pré-Alfa Inicial

As ISOs de prévia inicial (uma ou mais) destinam-se exclusivamente ao benefício do desenvolvimento interno, QA e usuários avançados.
Elas podem não funcionar de forma alguma ou podem exigir algumas opções especiais para sequer inicializar. De forma alguma, elas são destinadas a lançamentos públicos, nem são adequadas para qualquer tipo de avaliação.

### Pre-alpha

A pré-alfa refere-se a todas as atividades realizadas durante o projeto de software antes dos testes. No desenvolvimento típico de código aberto, existem vários tipos de versões pré-alfa. As versões de marco incluem conjuntos específicos de funções e são lançadas assim que a funcionalidade é concluída.

### Alpha

A fase alfa do ciclo de vida de uma versão é a primeira fase em que se iniciam os testes do software (alfa é a primeira letra do alfabeto grego, usada como o número 1).

O software alfa pode ser instável e pode causar travamentos ou perda de dados. O software alfa pode não conter todos os recursos planejados para a versão final.
A fase alfa geralmente termina com um congelamento de recursos, indicando que nenhum novo recurso será adicionado ao software. Nesse momento, diz-se que o software está com os recursos completos.

### Beta

Beta, nomeada em homenagem à segunda letra do alfabeto grego, é a fase de desenvolvimento de software que segue a alfa. A fase beta geralmente começa quando o software está com os recursos completos, mas provavelmente ainda contém vários bugs conhecidos ou desconhecidos.

Alguns desenvolvedores se referem a essa etapa como prévia, versão de prévia, protótipo, prévia técnica / prévia de tecnologia (TP) ou acesso antecipado.
Os testadores relatam quaisquer bugs que encontram e, às vezes, sugerem recursos adicionais que consideram que deveriam estar disponíveis na versão final.

### Candidato a lançamento

Uma versão candidata a lançamento (RC) é uma versão beta com potencial para se tornar o produto final, que está pronta para ser lançada, a menos que surjam bugs significativos. Nesta etapa de estabilização do produto, todos os recursos do produto foram projetados, codificados e testados durante um ou mais ciclos beta, sem nenhum bug conhecido de classe impeditiva.

Uma versão é considerada com o código completo quando a equipe de desenvolvimento concorda que nenhum código-fonte totalmente novo será adicionado a essa versão. Ainda podem ocorrer alterações no código-fonte para corrigir defeitos, alterações na documentação e nos arquivos de dados, além de código auxiliar para casos de teste ou utilitários.

Os testes são realizados para testar o software sob a perspectiva do usuário.

### Lançamento final - Disponibilidade geral (GA)

Após o lançamento, o software é geralmente conhecido como uma "versão estável".
