# Использование dnf в OpenMandriva Lx

> Полную документацию и дополнительные команды см. в **справочнике команд DNF**: [[dnf5]](https://dnf5.readthedocs.io/en/latest/index.html) [[dnf4]](https://dnf.readthedocs.io/en/latest/command_ref.html)
{.is-success}


## Основные команды

- Установить пакет:
`$ sudo dnf --refresh install <package_name>`

- Удалить пакет:
`$ sudo dnf remove <package_name>`

- Найти пакет в репозиториях:
`$ sudo dnf search <package_name>`
Примечание: команда 'dnf search' также поддерживает поиск по части названия пакета.

- Очистить кеш от оставшихся файлов и пакетов, а также удалить метаданные репозиториев:
`$ sudo dnf clean all ; dnf clean all`

- Обновить систему Rock:
`$ sudo dnf --refresh upgrade `

- Обновить систему Rolling:
`$ sudo dnf --refresh distro-sync `

## Другие распространённые команды dnf

`autoremove`
Удаляет пакеты, установленные в качестве зависимостей, которые больше не требуются установленным программам.
> Будьте внимательны при использовании команды `dnf autoremove`. Она вполне может удалить пакеты, которые вы хотели бы сохранить. Рекомендуется вести список автоматически удалённых пакетов, чтобы при необходимости знать, что нужно установить повторно.
Примечание: сведения об автоматически удалённых пакетах можно найти в `/var/log/dnf.log`.
{.is-warning}


`check-update`
Проверяет наличие обновлений, не скачивая и не устанавливая пакеты.

`downgrade`
Возвращает пакет к предыдущей версии.

`info`
Выводит основную информацию о пакете, включая название, версию, выпуск и описание.

`reinstall`
Повторно устанавливает уже установленный пакет.

`repolist`
Выводит список включённых репозиториев.

## Некоторые команды можно сокращать

`dnf in=dnf install`
`dnf ri=dnf reinstall`
`dnf dg=dnf downgrade`
`dnf rm=dnf remove`
`dnf up=dnf upgrade`
`dnf dsync=dnf distro-sync`

## Распространённые параметры dnf

`--allowerasing`
Разрешает удаление установленных пакетов для разрешения зависимостей. Этот параметр можно использовать вместо команды yum swap, если удаляемые пакеты не указаны явно. Применяйте его с осторожностью: неосторожное использование может привести к повреждению системы.

`-b, --best`
Предписывает использовать лучшие доступные версии пакетов при выполнении операций. В частности, команда dnf upgrade по умолчанию пропускает обновления, которые невозможно установить из-за проблем с зависимостями. Этот параметр заставляет DNF рассматривать только самые новые версии пакетов. Если зависимости нарушены, DNF завершит операцию с ошибкой и укажет причину, по которой последнюю версию невозможно установить.

`--disable, --set-disabled`
Отключает указанные репозитории (с автоматическим сохранением настроек). Параметр необходимо использовать совместно с командой config-manager (dnf-plugins-core).

`--disablerepo=<repoid>`
Отключает указанные репозитории по идентификатору или шаблону. Этот параметр несовместим с `--repo`.

`--downloadonly`
Скачивает выбранный набор пакетов с разрешёнными зависимостями без выполнения операций RPM (установки, обновления или удаления).

`--enable, --set-enabled`
Включает указанные репозитории (с автоматическим сохранением настроек). Параметр необходимо использовать совместно с командой config-manager (dnf-plugins-core).

`--enablerepo=<repoid>`
Включает дополнительные репозитории по идентификатору или шаблону.

`--exclude=<package_name>`
Исключает указанные пакеты из операции.

`--nobest`
Устанавливает для параметра best значение False, позволяя использовать не только наиболее предпочтительные версии пакетов.

`-y, --assumeyes`
Автоматически отвечает «да» на все запросы подтверждения.

## Дополнительная информация
`$ dnf --help`
and
`$ man dnf4` or `$ man dnf5` 

Ознакомление со справкой занимает примерно от одной до полутора минут, а чтение руководства man — около 3-5 минут.
Оба источника предназначены для того, чтобы пользователи могли быстро находить нужные команды и инструкции во время работы с системой.
