# Жизненный цикл выпуска ПО

По материалам [Википедии, свободной энциклопедии](https://en.wikipedia.org/wiki/Software_release_life_cycle)
*Свободно заимствовано и адаптировано.*


## Этапы разработки и финальный выпуск

### Предварительная версия и ранняя пре-альфа

Ранние предварительные ISO-образы (один или несколько) предназначены исключительно для внутренней разработки, тестирования командой контроля качества QA и опытными пользователями.
Они могут вообще не работать или требовать специальных параметров даже для загрузки. Эти образы ни в коем случае не предназначены для публичного выпуска и не подходят для каких-либо обзоров.

### Пре-альфа

Пре-альфа охватывает все этапы работы над программным проектом до начала тестирования. При разработке программного обеспечения с открытым исходным кодом обычно существует несколько типов пре-альфа-версий. Промежуточные выпуски Milestone включают определённый набор функций и выпускаются по мере завершения их реализации.

### Альфа

Альфа-этап жизненного цикла выпуска — это первый этап тестирования программного обеспечения (альфа — первая буква греческого алфавита, соответствующая числу 1).

Альфа-версия программного обеспечения может работать нестабильно, вызывая сбои или потерю данных. Кроме того, в ней могут отсутствовать некоторые функции, запланированные для финального выпуска.
Альфа-этап обычно завершается заморозкой функциональности, после которой добавление новых функций прекращается. К этому моменту считается, что реализация всех запланированных функций завершена.

### Бета

Бета-этап, названный в честь второй буквы греческого алфавита, следует за альфа-этапом разработки программного обеспечения. Обычно он начинается после завершения реализации всех запланированных функций, однако программа всё ещё может содержать ряд известных или пока не обнаруженных ошибок.

Некоторые разработчики называют этот этап предварительной версией, предварительным выпуском, прототипом, технической демонстрационной версией (TP) или ранним доступом.
Тестировщики сообщают обо всех обнаруженных ошибках, а иногда предлагают дополнительные функции, которые, по их мнению, следует включить в финальную версию.

### Кандидат в релиз

Кандидат в релиз (RC) — это бета-версия, которая потенциально может стать финальным выпуском, если не будут обнаружены серьёзные ошибки. На этом этапе стабилизации продукта все запланированные функции уже спроектированы, реализованы и протестированы в ходе одного или нескольких циклов бета-тестирования. При этом не должно оставаться известных критических ошибок, препятствующих выпуску.

Выпуск считается завершённым по программному коду (code complete), когда команда разработчиков решает, что новый исходный код, реализующий дополнительную функциональность, больше не будет добавляться в эту версию. При этом допускаются изменения исходного кода для исправления ошибок, обновления документации и файлов данных, а также добавление вспомогательного кода для тестов и служебных утилит.

Тестирование проводится для проверки работы программного обеспечения с точки зрения пользователя.

### Финальный выпуск — General availability (GA)

После официального выпуска программное обеспечение обычно называют "стабильным выпуском".
